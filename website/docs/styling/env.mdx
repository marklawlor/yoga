# Env Variables

Yoga supports CSS [`env()`](https://developer.mozilla.org/en-US/docs/Web/CSS/env)
variables on any length-accepting style property. An `env()` expression reads a
named value from the node's [Config](../getting-started/configuring-yoga.mdx),
resolved at layout time. Pass an expression string as the property value:

```jsx
<Node style={{ padding: "env(safe-area-inset-top)" }} />
```

In the example below, `banner-width` and `sidebar-width` are unset, so each
`env()` falls back to the value after the comma — on their own, inside a
`calc()`, and as a percentage:

<Playground code={`<Layout config={{useWebDefaults: false}}>
  <Node style={{width: 350, height: 350, padding: 10, gap: 8}}>
    <Node style={{width: "env(banner-width, 300)", height: 60}} />
    <Node style={{width: "calc(env(sidebar-width, 80) + 40)", height: 60}} />
    <Node style={{width: "env(missing, 50%)", height: 60}} />
  </Node>
</Layout>`} />

## Syntax

| Form                  | Example                          | Description                                                  |
| --------------------- | -------------------------------- | ------------------------------------------------------------ |
| `env(name)`           | `env(safe-area-inset-top)`       | The value of `name`, or undefined if `name` is unset         |
| `env(name, fallback)` | `env(banner-height, 20)`         | The value of `name`, or `fallback` if `name` is unset        |

If `name` is unset on the Config and no `fallback` is given, the expression
resolves to undefined and the property behaves as if it were not set.

`env()` composes with [Maths Expressions](/docs/styling/math-expressions), so an
env variable can be combined with other lengths:

```jsx
<Node style={{ paddingTop: "calc(env(safe-area-inset-top) + 16)" }} />
```

The `fallback` may itself be any expression, including a percentage or a `calc()`
(for example `env(sidebar-width, 25%)`).

## Naming

Env variable names are **host-defined**. Any string may be used as a name — Yoga
does not enforce a fixed set. A name consists of ASCII letters, digits,
underscores, and hyphens, and must begin with a letter, underscore, or hyphen.

Yoga pre-populates the four standard safe-area inset variables with a value of
`0`:

- `safe-area-inset-top`
- `safe-area-inset-right`
- `safe-area-inset-bottom`
- `safe-area-inset-left`

Hosts may override these defaults or remove them. All other names start out
unset.

Because the four `safe-area-inset-*` names are pre-set (to `0`), an `env()`
fallback on them is **not** used unless you first `removeEnv` the name — a set
value of `0` still counts as set. Fallbacks fire only for names that are unset,
which is why the `env(name, fallback)` example above uses a custom name.

## Setting values

Env variable values are set on a Config. The value is given in **points** — the
same unitless coordinate Yoga uses everywhere — and applies to every node
attached to that Config. (A `fallback` inside an `env()` expression may be a
percentage or a `calc()`, but the stored value itself is always a point value.)

<Tabs groupId="language">

<TabItem value="cpp" label="C/C++">

```cpp
#include <yoga/Yoga.h>

YGConfigRef config = YGConfigNew();

// Set a value (in points).
YGConfigSetEnv(config, "safe-area-inset-top", 44.0f);

// Read the stored value, or YGUndefined if it is unset.
// Note: this returns the stored value only; it does NOT apply any env()
// fallback.
float top = YGConfigGetEnv(config, "safe-area-inset-top");

// Clear a value. The name stays registered but resolves as unset, so any
// env() fallback (else undefined) is used instead.
YGConfigRemoveEnv(config, "safe-area-inset-top");
```

Passing `YGUndefined` to `YGConfigSetEnv` clears the variable, exactly like
`YGConfigRemoveEnv`.

</TabItem>

<TabItem value="java" label="Java">

```java
import com.facebook.yoga.YogaConfigFactory;

YogaConfig config = YogaConfigFactory.create();

// Set a value (in points).
config.setEnv("safe-area-inset-top", 44.0f);

// Read the stored value, or YogaConstants.UNDEFINED if it is unset. This
// returns the stored value only; it does NOT apply any env() fallback.
float top = config.getEnv("safe-area-inset-top");

// Clear a value. The name stays registered but resolves as unset.
config.removeEnv("safe-area-inset-top");
```

</TabItem>

<TabItem value="js" label="JavaScript">

```ts
import Yoga from 'yoga-layout';

const config = Yoga.Config.create();

// Set a value (in points).
config.setEnv('safe-area-inset-top', 44);

// Read the stored value, or NaN (undefined) if it is unset. This returns the
// stored value only; it does NOT apply any env() fallback.
const top = config.getEnv('safe-area-inset-top');

// Clear a value. The name stays registered but resolves as unset. Passing
// undefined to setEnv clears the variable in the same way.
config.removeEnv('safe-area-inset-top');
```

## Late binding and relayout

Env variables are resolved during layout, not when a style is assigned. This
makes them a natural fit for values that change at runtime, such as device safe
areas or a dynamic sidebar width.

Changing an env value on a Config (via `setEnv` or `removeEnv`) invalidates the
cached layout for every node under that Config. The new value is picked up on the
next `CalculateLayout`, so you can update a single env variable and relayout
without re-assigning any node styles.

## Supported properties

`env()` works on the same length-accepting properties as
[Maths Expressions](/docs/styling/math-expressions):

**Dimensions**: `width`, `height`

**Constraints**: `minWidth`, `minHeight`, `maxWidth`, `maxHeight`

**Flex**: `flexBasis`

**Spacing**: `margin` (all edges), `padding` (all edges)

**Position / insets**: `top`, `bottom`, `left`, `right`, `start`, `end`,
`insetInline`, `insetBlock`

**Gap**: `gap`, `rowGap`, `columnGap`
